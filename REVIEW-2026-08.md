# Full Site Test & UX Review — August 2026

Scope: every page in the repository, exercised in a real Chromium browser (Playwright) at
desktop (1440×950) and mobile (390×844), plus computational verification of clinical and
mathematical logic. 22 pages crawled, 4 simulator playthroughs, 3,416 BP-calculator
evaluations, all quiz answer keys verified.

**Overall:** the clinical and educational substance here is genuinely strong — the PHS case
design and the AAP 2017 spline implementation are better than most published equivalents.
The defects below are almost all in the *presentation and gating* layers sitting on top of
sound engines, which is the good kind of problem to have.

## P0 — Fix before further use

### 1. PHS: blood pressure always displays as `NaN`

`phs/v17/ui-core.js:formatVital()`

```js
function formatVital(k,v){if(k==='Lactate'||k==='Temp')return Number(v).toFixed(1);return String(Math.round(v*10)/10);}
```

BP is a string (`"62/38"`), so `Math.round("62/38"*10)/10` → `NaN`. Verified for every
patient in every state, including `"unobtainable"`:

| input | rendered |
|---|---|
| `BP "62/38"` | **NaN** |
| `BP "48/26"` | **NaN** |
| `BP "unobtainable"` | **NaN** |
| `HR 168` | 168 |

This is the primary vitals tile, and blood pressure is *the* discriminating vital in a
critical-coarctation case. The learner can only recover it from the smaller trend strip.

**Fix:** pass non-numeric vitals through untouched.

```js
function formatVital(k,v){
  if(k==='Lactate'||k==='Temp')return Number(v).toFixed(1);
  if(typeof v!=='number'&&isNaN(Number(v)))return String(v);
  return String(Math.round(Number(v)*10)/10);
}
```

### 2. PHS: the mastery standard is mathematically unreachable

A maximally efficient expert run — correct triage, disconfirming history first, four-limb
BPs, pre/post-ductal sats, monitor+IV, glucose, correct reasoning commitment, airway ready,
PGE, cultures, antibiotics, gas, echo, cardiology escalation with read-back, Eli on HFNC,
Nora's culture judgment + antibiotics + admit, Jamal's family update, all results reviewed
and interpreted, all pages acknowledged — **scores 70%. The mastery minimum is 80%.**

The run consumed the entire 900-second shift and auto-ended before I-PASS could be filled in.

| run | score | outcome |
|---|---|---|
| do nothing | 6% | Maya arrests |
| PGE, apnea never rescued | 31% | "shift interval ended" |
| thorough expert run | 73% | Maya stabilized |
| **ceiling run (everything right)** | **70%** | auto-ended at 900s |

Root causes, in order of impact:

- **Auto-end silently forfeits an entire objective.** `engine-core.js:47` ends the shift at
  `state.time>=900` with no warning. R17 (I-PASS completeness, 15 pts) and R18 (pending
  ownership, 8 pts) are the whole of objective O6 — 23 of 169 points. O6's minimum is 70%,
  so hitting 900s makes mastery impossible regardless of clinical performance.
- **The clock shows elapsed time only** (`fmtTime(state.time)`), never remaining.
- **R2 conflicts with R10 by construction.** R2 requires *all* urgent pages answered within
  90s; Eli's desat pages at 210s and Nora's culture at 300s land squarely inside Maya's
  stabilization window. No ordering satisfies both.

**Recommended:**
- Reserve handoff time: warn at 720s ("3 minutes left — begin end-of-shift handoff"), hard-stop
  clinical actions at 840s and open the end-of-shift modal automatically rather than ending.
- Show `remaining` next to elapsed in the topbar.
- Either raise R2's window to ~150s or make it proportional (credit per page answered)
  instead of all-or-nothing.
- Re-derive `overallMinimum` from an achievable-ceiling run rather than a round 80.

### 3. PHS: untreated post-PGE apnea has no consequence

Ordering PGE without airway support correctly schedules `pge-apnea` at +45s, which sets
`SpO2 68, HR 88`. But the post-treatment branch of `updateMaya()` runs every tick and
immediately walks SpO2 and HR back up, and sets `stabilized` at `since>=120` unconditionally.

Verified end state of a run where airway was **never** ordered:

```
flags: {pgeStarted, pgeApnea: true, critical: true, responding: true, stabilized: true}
vitals: SpO2 71.4%, BP 70/44, HR 150
end:    "The scheduled shift interval ended."
```

A 6-day-old at 71% saturation with untreated apnea for eleven minutes ends the shift flagged
both `critical` and `stabilized`, and the learner is told the shift simply ended. This
disarms the single most important safety lesson about prostaglandin.

**Fix:** gate the recovery branch on `!p.flags.pgeApnea`, and give unresolved apnea its own
deterioration path to arrest.

### 4. BP calculator: classification contradicts its own displayed thresholds

`classify()` decides Elevated/Stage 1 from a **rounded integer percentile**
(`findPercentile`, nearest of 99 discrete values) while the thresholds shown to the user come
from the **continuous** spline (`getBPAtPercentile`). They disagree at the boundary.

Sweep of 2 sexes × 4 ages × 7 heights × SBP 85–145 (3,416 evaluations) found **18
contradictions**, e.g.:

| case | patient SBP | displayed 95th | classification shown |
|---|---|---|---|
| M, 12y, 130 cm | 113 | **113** | Elevated BP |
| F, 6y, 120 cm | 111 | **111** | Elevated BP |
| M, 10y, 120 cm | 110 | 111 | **Stage 1 HTN** |
| F, 12y, 110 cm | 114 | 115 | **Stage 1 HTN** |

A clinician reading "95th percentile: 113" for a patient at 113 is told "Elevated BP".

**Fix:** classify from the same continuous values already computed for display.

```js
// in classify(), for age < 13 — replace percentile-rank tests with value tests
if (sbp >= sbp95 || dbp >= dbp95 || sbp >= 130 || dbp >= 80) return Stage 1;
if (sbp >= sbp90 || dbp >= dbp90 || sbp >= 120) return Elevated;   // pass sbp90/dbp90 in
```

Keep the integer percentile for *display* only. This also removes the "±1 percentile" caveat
from anything that affects a clinical category.

## P1 — Correctness and safety gaps

### 5. BP calculator accepts physiologically impossible input

`calculate()` validates age and height presence, but not plausibility. All of these return a
confident classification with no warning:

| input | result |
|---|---|
| 60/90 (DBP > SBP) | **Stage 2 HTN** |
| SBP 400 | Stage 2 HTN |
| SBP −50, DBP −20 | **Normal** |
| height 500 cm | Normal |
| height "130 **in**" (=330 cm) | Normal |

The `min`/`max` attributes on the inputs are never enforced in JS. Add: `dbp < sbp`,
`50 ≤ sbp ≤ 250`, `30 ≤ dbp ≤ 150`, and a height sanity band per age (the height z-score is
already computed — reuse it to hard-block beyond ±4 SD rather than only warning at ±3.09).

### 6. BP calculator shows stale results after inputs change

Calculate 126/88 on an 8-year-old → "Stage 2 HTN". Change the fields to 90/50 without
pressing Calculate: **the Stage 2 HTN panel stays on screen next to the new numbers.**

Add `oninput` handlers on all six fields that call `results.classList.remove('show')`.

### 7. Ordinal suffixes are hardcoded `'th'`

`bp-percentile-calculator.html:903,905` — `sbpPct + 'th %ile'`. Produces "1th", "3th",
"23th", "41th", "92th". Small, but it is the largest text on a clinical result card.

```js
const ord=n=>{const a=n%100,b=n%10;return n+((a<11||a>13)&&b<4&&b>0?['st','nd','rd'][b-1]:'th');};
```

### 8. BP calculator has no form semantics

There is no `<form>`, so Enter does nothing — verified: pressing Enter in the DBP field does
not calculate. Six inputs have `<label>` elements with no `for` attribute and no wrapping,
so screen readers announce them unlabeled. Wrap in `<form onsubmit="calculate();return false">`
and add `for`/`id` pairs.

### 9. The two best things on the site are unreachable

Neither `/phs/` nor `/math/` is linked from anywhere — not the homepage, not `/tools/`, not
`/study/`, not the README. Verified by grepping every `href` in the repo.

The Pediatric Hospital Simulator — 6 objectives, 18 rubric items, 4 declarative case files,
a deterministic physiology engine, structured debrief, mastery loop — is reachable only by
typing the URL. Math Lab is the most polished page in the repo (it is the only one with a
skip link and focus styles) and is equally invisible.

Add both to the homepage card grid. PHS deserves top billing.

also refers to a "homework tracker at /twins/" and titles a section "Adding a Study Tool

## P3 — Accessibility

Measured with a WCAG contrast pass and keyboard-reachability check.

| Finding | Where |
|---|---|
| **Study-tool menus are keyboard-inaccessible** — mode selection uses `<div class="menu-card" onclick>`; the menu screen of every quiz has **0 tabbable elements**. The answer choices are proper `<button>`s, so only the entry point is broken. | all 5 `study/*.html` |
| **No `:focus` styles** — keyboard users get no visible focus ring | `/`, `/study/*`, `/phs/` |
| Body text below 4.5:1 — `#718096` on white = **4.02:1**; badge text `#fff` on light purple/orange = **3.66:1** | `/study/` cards |
| `#64748b` "Female" toggle = 3.86:1 | BP calculator |

| 13 unlabeled inputs (I-PASS + reasoning fields) | `/phs/` |

### 14. Math Lab loads Google Fonts from a CDN

`math/index.html` requests `fonts.googleapis.com` — this violates the "no external
dependencies" rule in CLAUDE.md, and it was the only network failure in the entire crawl
(`ERR_TUNNEL_CONNECTION_FAILED`), which drops the page to fallback fonts. Self-host or drop
to the system stack.

## What's working well

Worth stating plainly, because it's most of the codebase:

- **PHS case design is excellent.** All four sign-outs encode a real cognitive trap: Maya's
  "probably feeding adjustment", Nora's "I would not disturb her", Eli's "just needs time",
  Jamal's family pressure toward a CT. The three variants rotate the inherited frame
  (reassurance / sepsis / accurate-but-incomplete) so a repeat attempt isn't a memory test.
- **The physiology engine models time-to-treatment properly.** Recovery target is a step
  function of when PGE started (`≤240s → lactate 2.5`, `≤360s → 3.7`, else `5`). Verified:
  PGE at 170s ended at BP 70/44, lactate 2.5; PGE at 315s ended at 64/38, lactate 3.7. Late
  rescue is survivable but visibly worse — exactly right.
- **The 20 mL/kg bolus trap works.** Novice path (sepsis frame + big bolus) drove BP 62/38 →
  48/26 and lactate 3.1 → 5.6 with rising RR. Correct physiology for fluid loading an
  obstructed left heart, and a far better teacher than a text explanation.
- **The rubric carries `rationale` *and* `consequence` per item** — debriefs explain what the
  miss would have cost the patient, not just that points were lost.
- **`phs/v17/tests/integrity.mjs` passes** and is wired to CI: 9 runtime files, 5 case files,
  6 objectives, 18 rubric items, 3 variants. Declarative case authoring with a JSON Schema is
  the right architecture.
- **The AAP 2017 implementation is faithful.** Full spline reconstruction with sex-specific
  knots, CDC LMS height z-scores, correct "whichever is lower" logic for under-13s, correct
  adolescent thresholds, and honest extrapolation warnings outside 5–17y. Spot-checked against
  published tables: 8-year-old boy at 50th height → 90th 110/72, 95th 114/75.
- **Cooking timers are solid.** Verified wake lock, Web Audio alerts, notifications, print CSS,
  pause/back/skip/±30s, and localStorage resume that **correctly accounts for wall-clock time
  while the tab was closed** (rewound a saved start by 5 min → remaining went 14:57 → 9:56).
- **All quiz answer keys are correct.** 11 computationally verifiable fraction items in
  `topic-e-quiz.html` all check out; no answer-missing-from-choices, no duplicate choices.
  Multi-select ("Select both") works correctly.
- **Zero JavaScript errors** across every page except the Math Lab font fetch.

### Two content items to review

- `topic-e-quiz.html`: two distractors are *numerically equal* to the keyed answer —
  "7 × 1/4" keys `1 3/4` with `7/4` offered, and "Write 17/5 as a mixed number" keys `3 2/5`
  with `2 7/5` offered. Both are defensible form-vs-value distractors, but a 4th grader who
  converts back and checks will get a correct value and be marked wrong. Make the explanations
  address the form point explicitly.
- `greek-vocab-quiz.html`: "Who qualified for citizenship in ancient Athens?" is keyed
  **"wealthy men"**. Athenian citizenship required free adult males of Athenian parentage;
  wealth (the Solonian classes) gated *office-holding*, not citizenship or assembly voting.
  If this matches the classroom text, leave it and note the nuance in the explanation.
